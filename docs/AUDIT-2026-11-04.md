## D · Dispatcher status

*Implemented, tested, not operationally verified, not activated.*

`node agent/release/cli.mjs dispatch --proposal <id> [--execute --as-of …]` runs nine stages — intake, ledger, approval,
preflight, duplicate, isolate, apply, scope, commit — and **refuses, in order**: a malformed id; a ledger with any chain,
signature, fixture or agent-decider problem; a decision that is not `granted`, not signed by a registered reviewer, or void
(pending, denied, scope changed, simulated, self-approved); a proposal failing Agent 9's ten gates; an approval of content
already dispatched on *any* branch (the duplicate returns the first commit, derived from `git log --all --grep Dispatch-Key`);
execution from `main` or over uncommitted work in scope; an applier that does not report `implemented`; a change outside the
approved paths. It **never** pushes, merges, writes the ledger or approves. A rehearsal (the default) leaves git byte-identical.
Every attempt, refusals included, is a line in `agent/release/runs/dispatch.jsonl` (git-ignored) and in the returned report.

Tested (`agent/release/selftest.mjs` A1–A12, on temporary repositories): rehearsal; one commit with the trailers
`Proposal`, `Proposal-SHA256`, `Approval`, `Dispatch-Key`, `Decided-By`, `Evidence`; duplicate; pending, forged-granted,
no-request, denied, edited-after-approval, unproducible-proposal; unsigned, simulated, tampered, unregistered-key; eleven hostile
inputs; main and dirty scope; four applier failures; out-of-scope and no-op changes; static check that the module contains no
push, merge, reset, `--force` or `recordDecision(`; the seven lifecycle states and `published` via a real merge.

**Not verified:** Agent 9's *real* apply path end to end. The tests use a stub for the applier because the real one runs the
validators and suites (minutes) and no real proposal exists. Wiring, injection and the rehearsal path are tested.
**Not satisfied:** the readiness condition `production_dispatcher_wired` — see F3/F4.

## E · Attestation status

*Mechanism implemented and tested. **No authentic human approval exists. None was made.***

- **Structure:** `verifyLedger()` validates every field, timestamp, the chain (`seq`, `prev_entry_sha256`, `entry_sha256`), the
  snapshot's hash, provenance/label consistency, agent deciders, signatures against `reviewers.json` (active, name- and
  role-matching). Version-1 lines are refused. (B1–B9.)
- **Human ≠ automated:** `provenance: "human" | "simulated"`; a simulated entry must be named `SIMULATED: …`, cannot be signed,
  is `void_simulated` to `deriveApproval`, and is refused by the dispatcher and the gate. Automated validation (preflight, QA)
  lives in the proposal/ChangeRecord, never in a decision line.
- **No self-approval:** refused at write (`recordDecision`), on read (`deriveApproval`), and on verification against the
  *whole* capability register — stronger than the writer, which knows only the agents of the store it was handed (B6).
- **Lifecycle:** `lifecycleOf()` derives proposed / technically validated / awaiting human review / approved / rejected /
  published / superseded-or-withdrawn (+ `invalid`, `unknown`) from proposal, ledger and git — stored nowhere. `published`
  means *merged to main*; the deploy itself is GitHub's record.
- **What the owner must do** (`docs/DEPLOYMENT.md` §3b): generate a key outside the repository (`keygen`), register it in
  `reviewers.json` in a pull request they review, pin the registry fingerprint as the repository variable
  `RELEASE_REVIEWER_REGISTRY_SHA256`, and — per proposal — inspect what the `ApprovalRequest` asks (`evidence`,
  `proposed_change.operations` with `current`/`proposed`, `risk`, `rollback_plan`, `what_to_check`), then run `decide … --sign-key`.
- **What it still cannot show:** who holds the private key; that the registry is honest (only the external pin and branch
  protection say so); that the person read what they signed. The Control Room's decisions are unsigned (F5).
- **Fixtures cannot pass as approvals:** every fixture lives in a temporary directory under a per-run key; the suite hashes
  the real decisions directory (R1) and fails if a fixture name or a `SIMULATED:` entry is found there.

## F · Deployment-gate status

*Implemented and wired into `pages.yml`'s `build` job; tested locally against a real artifact and temporary histories;
**has not run in GitHub Actions**; the external settings are not set.*

`build` → artifact built → `agent/release/cli.mjs gate --ci …` → `configure-pages` → `upload-pages-artifact`. A failing gate
leaves nothing to upload. Ten conditions (`docs/DEPLOYMENT.md` §2a, `agent/release/README.md`): origin, history, publisher
integrity, upstream results, ledger, append-only, agent changes (precede / signed / in scope / unwithdrawn / ≤ 30 days / hash and
key match), unledgered (reported), artifact (allowlist + byte-identity to the commit's blobs + credential scan), registry pin.
An *unmeasured* condition blocks in CI.

**Bypass scenarios tested** (negative, each fails the gate): a second publisher in five forms; a trigger other than push-to-main
or dispatch; each of `needs`, `if:`, `continue-on-error`, `|| true`, `set +e`, a moved or deleted gate step, `write-all`, a
stray `pages: write`; a fork, a feature branch, a pull request, a different workflow, a different SHA, a checkout that is not the
judged commit; each upstream gate job failing, cancelled or skipped; no decision, unsigned, unregistered key, revoked reviewer,
simulated, edited line, hash/key mismatch, out-of-scope file, approval after the change, stale approval, decision dated after
the commit, later withdrawal, an agent registering its own key (stopped only by the pin); an extra file, a changed byte, a
missing file, a dot path or a credential in `_site`. **Positive:** a full clean pass (G1), the honest ordered history (G8), a real
118-file artifact from `HEAD` (G7). Reproduce: `node --test agent/release/selftest.mjs`; in CI: `qa.yml`.

**External configuration still required** (none readable from the tree): ruleset on `main` with required review and the `qa.yml`
checks; `CODEOWNERS` over `.github/`, `agent/release/`, `agent/implement/decisions/`, `tools/pages-artifact.mjs`; the
`github-pages` environment limited to `main`; the registry-pin variable; confirmation that Pages' source is "GitHub Actions"
(reported done 24 Oct 2026, not re-measured). `docs/DEPLOYMENT.md` §3a.
