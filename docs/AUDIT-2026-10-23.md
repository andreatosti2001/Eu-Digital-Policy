## 1. The failing QA workflow — root cause found and fixed

**Evidence:** the raw log of QA run 39770094879 (job "Browser regression suite") *was* retrievable
through the GitHub API this session. It shows the cause; nothing below is inferred from the failed
step's name alone.

- The runner image (ubuntu-24.04, `20261012.334.1`) already ships Chromium in
  `/usr/local/share/chromium` with `/usr/bin/chromium` and `/usr/bin/chromium-browser` linked to it,
  and Google Chrome (`actions/runner-images`, `install-google-chrome.sh`; the image README lists
  both).
- The step ran `apt-get install chromium-browser`. On Ubuntu 24.04 that is a transitional package
  that **replaces** the link with a wrapper around the chromium snap, downloaded from the snap store
  on every run. On 22 Oct the store answered **HTTP 408** for the `mesa-2404` content snap; apt
  failed; `|| apt-get install chromium` installed the same transitional package over the
  half-installed snap and reported success; the next step's `--version` printed "Content snap GPU
  wrapper … not found: ensure slot is connected" and **exited 3**. The Pages gate on the same commit
  passed only because its snap download succeeded.
- **Fix** (`qa.yml` job `browser`, `pages.yml` job `gate-browser`): use the image's browser, chosen
  only if it actually runs `--version`; apt only when the image has none, with its failure no longer
  masked. "Report which browser this run used" is unchanged in `qa.yml` and added to `pages.yml`.
  Nothing was relaxed: the suite still runs with `--require-browser`.
- **Tested:** the exact `run:` blocks were parsed from both workflow files and executed with stub
  browsers: the old step reproduces exit 3 with the logged message; the new one skips a broken
  candidate, picks a working one, and fails when nothing works. **Not tested:** a real GitHub run —
  that needs a push, which was not made.
