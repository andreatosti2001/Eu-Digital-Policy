## Summary

This is a well-built project with an unusually honest README, and the audit
should say so before it says anything else: the evidence-grade model is derived
rather than stored and I reproduced its output exactly; the enforcement pipeline
refuses to turn unknown into zero; the applicability engine refuses to turn
absence of a rule into a negative finding; `renderError` refuses to substitute
fallback data. Those are the right decisions and they are implemented as
described.

The debt is not in the model. It is in **everything that surrounds the model**:
the gates that are documented but never run, the second copy of the brief's
facts that no validator can see, the one-shot data-patch scripts that are still
loaded and still runnable, and a commit history that cannot support the rollback
those scripts depend on.

Findings are ordered by what they would cost if acted on wrongly, not by how
easy they are to fix.

## P0 — Critical

### F-01 · [RETRACTED — replaced] A stale base read as a repository fact

**Original claim, now withdrawn:** that the three documents SESSION 01 named as
inputs did not exist.

**What is actually true.** They exist and are substantial, added by SESSION 00
in `c2e62c7` on `main`:

```
$ git rev-list --all --objects | awk '{print $2}' | grep '\.md$'
docs/AI-SAFE-BOUNDARIES.md      9,800 bytes
docs/CURRENT-ARCHITECTURE.md   20,740 bytes
docs/PROJECT-CONTEXT.md         6,984 bytes
docs/HANDOVER.md               11,274 bytes
.agents/skills/{project-context,repository-audit,data-governance,git-workflow}/SKILL.md
```

This branch was cut from `7248290`. SESSION 00 landed at `c2e62c7` afterwards.
`ls docs` on a stale working tree returned "No such file or directory", and I
reported that as a property of the repository **without running `git fetch`**.
The repository-audit skill SESSION 00 wrote — which I had not read, because it
was in the commit I had not fetched — opens its procedure with
`git branch -a`. That step would have caught this immediately.

**The real finding, which stands.** The failure is not that documents were
missing; it is that an agent working from a feature branch has **no signal that
its base is stale**. There is no CI, no `.github`, no branch-protection status,
and the repository's default `git log` shows only the branch's own ancestry. A
second agent starting today from `7248290` would reach the same wrong
conclusion by the same route.

**What this changes downstream.** F-04, F-05 and F-06 were reached independently
of SESSION 00 and are unaffected. F-07 is materially narrowed (see below). The
constitution delivered with this audit was rewritten to build on the SESSION 00
documents rather than to replace them.

**Mitigation for the constitution:** every session must run `git fetch --all`
and `git branch -a` before concluding anything about what the repository
contains. This is now the first step of `AGENTS.md` → *Before proposing
anything*, and is why `docs/AGENT-CONTRACTS.md` H2 says uncertainty survives a
handoff at full strength.

*Category: context-dependent assumptions; observability blind spot — mine, and
the repository's.*

### F-02 · Every gate the README describes is unenforced

README: *"`design-qa.mjs` exits non-zero on an error, so it can gate a commit."*

```
$ ls .github .claude          → No such file or directory
$ find . -name "package*.json" → (nothing)
$ ls .git/hooks | grep -v sample → (no active git hooks)
```

There is no CI workflow, no package manifest, no pre-commit hook. All four
validators are manual, opt-in, and run only when a human remembers. The word
"can" in that sentence is doing load-bearing work that a reader will not notice.

The consequence compounds with everything below: the repository *reads* as
validated. `validate.mjs` exits 0, `design-qa.mjs` exits 0, `i18n-audit.mjs`
reports `ERRORS 0 WARNINGS 0`. None of that was checked by anything except me,
today, by hand.

*Category: unsafe automation; weak validation; false confidence.*

### F-03 · Two re-runnable destructive data patches with frozen dates

`tools/_refsweep.mjs` is described in its own header as a *"one-shot data
patch"*. It is still present, still imports `writeFileSync`, and still runs.
What it does when run (lines 230–269):

```js
const SWEEP = '2026-08-28';
Object.assign(s, patch, { accessed: SWEEP });      // over live source records
c.last_verified   = patch.last_verified;           // overwrites, unconditionally
c.verification_note = patch.verification_note;     // overwrites, unconditionally
else { delete c.reference_gap; delete c.gap_note; }
sources.$last_verified = SWEEP;
write('data/sources.json', sources);
write('data/claims.json', claims);
```

Run it in six months and it silently rewrites every field it touches back to its
August 2026 values, re-dates the verification to `2026-08-28`, and **deletes**
`reference_gap`/`gap_note` on any claim whose patch entry has no `gap` — erasing
later human work and re-stamping it as verified. There is no dry-run, no
`--force`, no state check, no backup, no confirmation prompt.

`tools/_review10.mjs` is the same class: blind `String.split(from).join(to)` over
the whole of `index.html` with no occurrence-count assertion (`n === 0` only
logs `NOT FOUND` and continues), plus unbounded appends to `superseded` arrays in
`i18n/locales.json`. Its own comment concedes the blast radius: *"the string also
appears inside the inlined `__CONTENT__` search index"*.

The stated rollback path is `git`. See F-06 for why that is not a rollback path.

*Category: unsafe automation; missing rollback.*

### F-04 · A second, unvalidated copy of the brief's facts — with its own ID namespace

`index.html:361` inlines **59,817 bytes** of JSON as `window.__CONTENT__`, with
keys `meta`, `nodes[6]`, `nav[14]`, `search[13]`. `tools/validate.mjs` reads
`data/*.json` and nothing else. It has never seen this object.

Verified duplications:

| Fact | Canonical home | Second home | Agreement |
|---|---|---|---|
| 14 part titles | `data/brief.json` `parts[].title` | `__CONTENT__.nav[].title` | byte-identical (script-checked) — two homes for one fact |
| Instrument short/full name, brief_part | `data/instruments.json` | `__CONTENT__.nodes[]` | **disagree** |
| Brief prose | markup in `index.html` | `__CONTENT__.search[].text` | third copy, in the same file |

The disagreements are concrete:

- `__CONTENT__.nodes` uses `aiact` and `dataact`. The canonical IDs are `ai-act`
  and `data-act`, and neither short form appears in that instrument's `aliases`
  array. This is a **second, undeclared ID namespace**, and it is written into
  the SVG system map (`data-node="aiact"`, `index.html:142`) and the node cards
  (`index.html:144`).
- `nodes[].full` for `gdpr` is `"General Data Protection Regulation"`.
  `instruments.json` `full_name` is `"Regulation (EU) 2016/679 on the protection
  of natural persons…"`. Two values, same field, neither marked as the display
  form of the other.

**And the generator is not in the repository.** `app.js:588`:

```js
/* ---- search index self-heal: some search entries (e.g. annexes) ship with
   an empty text field from the generator; backfill from the rendered DOM ---- */
```

The README states flatly: *"**There is no generator.**"* Running code disagrees
with it, and carries a runtime workaround for that generator's known defects.
So `__CONTENT__` is a build artefact whose builder is absent, whose output is
patched by hand-written scripts, and which no validator checks — while the
README's headline principle is "one home per fact".

**Corroborated and extended by SESSION 00.** `docs/CURRENT-ARCHITECTURE.md` §8
reached this finding independently, and found two things this audit missed:

1. **`data/brief.json` is validated but never fetched.** No module loads it. The
   only four `'brief'` occurrences in `js/` are nav-model IDs in `js/shell.js`
   (35, 215, 230, 247). I verified this: `validate.mjs` checks `brief.parts` and
   `brief.reading_graph` in full, and nothing at runtime reads the file. The
   canonical dataset is dead; the uncontrolled copy is what the reader sees.
2. **`meta.standfirst` has already drifted**, which I did not catch because I
   compared only the 14 part titles. Confirmed:
   ```
   brief.json  : "Six regulations, one directive family and a live reform package now govern…"
   __CONTENT__ : "Six regulatory regimes — regulations, a family of directives and a live reform package — now govern…"
   IDENTICAL   : false      (meta.title/subtitle/dateline/note/howto all still agree)
   ```

**What this audit adds: the cause, and therefore which copy is stale.**
SESSION 00 recorded the drift and correctly declined to pick a winner. The
provenance is recoverable, and it is F-03 causing F-04:

`tools/_review10.mjs:54` carries exactly this edit —

```js
{ key: 'portal.p1',
  from: 'Six regulations, one directive family and a live reform package now govern',
  to:   'Six regulatory regimes — regulations, a family of directives and a live reform package — now govern' },
```

— under the review note *"P2.1: the six subjects are not six regulations. The
cyber layer alone contains two directives and two regulations."* And the script
opens exactly two files:

```
$ grep -n "read\|writeFileSync" tools/_review10.mjs
96:  let html = readFileSync('index.html', 'utf8');
110: writeFileSync('index.html', html);
```

It never opens `data/brief.json`. So on 28 August 2026 the correction was

**`data/brief.json` therefore carries the factual miscount the external review
already identified and corrected.** That is not a stylistic difference between
two drafts; it is a stale copy of a sentence the project has already ruled
wrong. I am not changing it — which copy ships is the author's decision and
`docs/HANDOVER.md` reserves it — but the decision is now evidenced rather than
a coin toss.

*Category: duplicated sources of truth; hidden coupling; missing provenance;
architectural inconsistency; unsafe automation (F-03 is the mechanism).*

### F-05 · `superseded` is an unverifiable assertion, and the locales already disagree

`i18n/locales.json` declares a key `superseded` when its translation no longer
describes the English. Checked across the three locales:

```
union of superseded keys: 10
  ASYMMETRIC annex-a.figcaption1 — present in: fr,es   MISSING from: it
```

`i18n-audit.mjs` output confirms the split: `it` → 21 absent / 9 superseded;
`fr` and `es` → 22 absent / 10 superseded. **It reports 0 errors**, because it
only checks that *absent* keys are *declared*. A key that is present cannot be
flagged, so a stale translation is invisible to it by construction.

This is the exact failure `_review10.mjs`'s header says phase 5 already caught
once, *with the Annex A captions* — and `annex-a.figcaption1` is the key that is
now asymmetric. Whether Italian is stale or French and Spanish over-withdrew is
not decidable from the repository, and no tool can decide it: `superseded` is a
claim about semantic equivalence between two natural-language strings.

*Category: weak validation; observability blind spot.*

### F-07 · The "phase record" the tooling defers to does not exist

`tools/_review10.mjs:5`: *"Points the review raised that were already satisfied,
or that attacked wording the brief does not use, are not here — they are listed
in the phase record instead."* README refers to phases repeatedly (*"has not for
several phases"*, *"the failure phase 5 caught"*).

No phase record is in the repository, and `git rev-list --all --objects` confirms
no file of that description has ever been committed. The reasoning for **what
was deliberately not changed** — the most valuable half of a review — is
unrecoverable. A future agent re-raising those points has no way to learn they
were already considered and rejected, and will re-litigate them.

**Narrowed by SESSION 00.** `docs/HANDOVER.md` now establishes the session-record
convention this finding asks for — objective, files changed, decisions, tests,
known limitations, unresolved issues, next session. That closes the gap going
forward. It does not recover the phase record, so the pre-SESSION 00 reasoning
remains lost; the finding stands for that period only.

*Category: missing provenance.*

### F-08 · The README hardcodes derived counts while asserting it cannot drift

README: *"The bibliography computes and states the current count on every load,
**so this README cannot drift from it**."* It then states four derived figures in
prose: 40 / 9 / 22 / 3.

I re-implemented `evidenceGrade` from `js/format.js` against `data/` and ran it:

```
TOTAL CLAIMS: 91
GRADE TALLY: {primary:25, official:7, secondary:6, interpretation:31, unresolved:22}
claims whose every DIRECT source is src-brief-original: 40
claims with no direct source at all:                     9
sources with url_status url:none:                        3
```

**All four reproduce exactly.** Credit where due — this is a carefully
maintained document. But the guarantee in that sentence is rhetorical: the
numbers are typed into Markdown, nothing compares them to the data, and the
next data change breaks them silently. The claim of drift-immunity is itself the
defect, because it tells a reader not to check.

*Category: weak validation; false confidence.*

### F-09 · The brief runs a second, older application architecture

`app.js` — 1,455 lines, 62 KB, at the repository root, an IIFE using `var`, not
an ES module — sits outside the `js/` module system the README presents as *the*
architecture. It owns the portal, the rota, the contents tree, glossary
popovers, i18n application, the scroll/progress pass and the prose search
provider, and it reads the `window.__CONTENT__` global.

`js/shell.js:19` makes the split explicit and permanent:

> *"It deliberately does NOT take over the brief's own top bar. That bar carries
> the reading lens, the contents tree, the reading progress and the language
> menu, **all bound by id in app.js**."*

So the coupling between the two architectures is by DOM id and one global
variable — the two weakest contracts available — and it is documented as a
decision rather than as debt. `design-qa.mjs` treats `app.js` as a peer of
`js/*.js` for custom-property harvesting but the `localStorage`-safety check
iterates `js/` only, so `app.js`'s three `localStorage` call sites are outside
that check (they do happen to be wrapped in `try`).

*Category: architectural inconsistency; hidden coupling.*

### F-10 · `design-qa.mjs` harvests CSS token declarations out of JavaScript by regex

`tools/design-qa.mjs:150`:

```js
for (const m of js.matchAll(/(--[a-z0-9-]+)\s*:/gi)) declared.add(m[1]);
```

Any occurrence of `--foo:` anywhere in any JS file — inside a string, inside a
comment, inside an unrelated CSS snippet — registers `--foo` as *declared*, and
thereby suppresses the `uses undeclared custom property` **error** for it
elsewhere. The check that the README presents as catching "the class of defect
that survives a visual review" can be silenced by a comment.

It currently reports two real warnings (`--tx`, `--ty` never set), which is
evidence the check works at all — not evidence that its negative results mean
anything.

*Category: weak validation; hidden coupling.*

## P2 — Medium

### F-11 · Dead and permissive checks inside `validate.mjs`

Two specifics:

1. **A check that can never fire.** `tools/validate.mjs:168`, in the competence
   loop:
   ```js
   checkOne(`${w}/competence`, 'institution', null);
   ```
   The third argument is the literal `null`, and `checkOne` returns immediately
   on `null`. Competence rows are never checked against an institution
   reference. The line reads as coverage and provides none.

2. **A wildcard reference can never dangle.** `resolves()` returns `true` for
   the bare string `'*'` unconditionally, and for any `foo*` if *any* ID starts
   with `foo`. `data/institutions.json` contains 5 bare `"*"` references and
   three wildcard institutions (`dpa-*`, `dsc-*`, `nca-*`). Referential
   integrity is therefore not enforced on that path — and `js/dna.js:58`
   builds real display logic on the same string-prefix convention.

*Category: weak validation.*

### F-12 · `freshness.mjs` reports reachability it never measures

The section is titled **SOURCE REACHABILITY** and prints:

```
3 url:none · 73 url:live · 1 url:paywalled
```

Those counts are read from the stored `url_status` field. The script is
zero-dependency and performs no network I/O. **No URL in this repository has
ever been tested.** `url:live` is an assertion made by whoever last edited the
record, presented under a heading that means "we checked". Link rot — the exact
failure the `EXPECTED.sources` interval exists to catch — is structurally
invisible.

Separately, the script currently prints *"Nothing past its stated interval"*
while also reporting the newest enforcement decision is **38 days** old against a
**45-day** interval, and that 10 of 16 enforcement records are flagged
`requires_verification`. The green line is 7 days from flipping, and nothing
watches it. The `EXPECTED` intervals themselves are unsourced editorial
judgements presented as thresholds.

*Category: observability blind spot; weak validation.*

### F-13 · `last_verified` is a batch stamp wearing a per-record name

Every dataset carries a single `$last_verified` of `2026-08-27` or `2026-08-28`,
and per-record `last_verified` values are written in bulk by the sweep scripts
to that same constant (`SWEEP`). The README states this plainly (limitation 2)
and `freshness.mjs` says so too — the honesty is real. The structural risk is
that the *schema* offers a per-record field, so a future agent reading
`claim.last_verified = "2026-08-28"` has no way to distinguish "this claim was
checked that day" from "this claim was in a file that was stamped that day".

*Category: weak validation; context-dependent assumptions.*

### F-14 · Observability blind spots

Beyond F-12, after deployment nothing is knowable:

- Failures surface as `console.error` and an in-page notice. `js/data.js`
  `renderError` is exemplary — it refuses to fabricate fallback data — but
  nothing is recorded anywhere a maintainer would see it.
- A missing or malformed locale file is swallowed to `{}` by `loadOverlay`,
  documented as *"the defined behaviour, not an error"*. Every string then falls
  back to English and is marked EN in the interface. A reader sees a degraded
  page; nobody learns the file 404'd.
- Three different "as of" dates describe the same artefact from three homes:
  README (*28 August 2026*), the generated footer (*© 2026*), and
  `__CONTENT__.meta.dateline` (*State of play as of 19 August 2026*).

*Category: observability blind spots; duplicated sources of truth.*

### F-15 · Context-dependent assumptions that are not declared

- **Deployment origin is compiled in.** `tools/_footer.mjs:15`
  `BASE = 'https://andreatosti2001.github.io/Eu-Digital-Policy/'`, and
  `design-qa.mjs` errors if any page's canonical URL disagrees. The check
  therefore confirms *consistency with a hardcoded assumption*, which will read
  as a correctness check to whoever moves the site.
- **The reader's clock changes derived output.** `js/pipeline.js` and
  `js/format.js` compute `isPast` against `new Date().toISOString()` (UTC). The
  `stage:law` pipeline state, the compliance calendar and the status strips all
  depend on when and where the page is opened. Nothing states this, and the
  pipeline is presented as derivation from the record.
- **Reports are not reproducible.** `freshness.mjs` takes its as-of date from
  `process.argv[2]`, defaulting to today, and records nowhere which date
  produced a given output.
- `_refsweep.mjs` and `_review10.mjs` hardcode `2026-08-28`.

*Category: context-dependent assumptions.*

### F-16 · Unnecessary complexity

- **A record and a runnable patch are the same file.** `_refsweep.mjs` (269
  lines) and `_review10.mjs` (125 lines) exist to make past edits auditable —
  a good reason — but they are kept in executable form with write access to the
  canonical data. The provenance value would survive them being inert.
- `design-qa.mjs` reads all seven pages from disk three separate times (HTML
  pass, custom-property harvest, footer/notice pass).
- **"One search surface" is one renderer over two retrieval implementations.**
  README: *"`js/palette.js` is the one search surface."* True of the UI. But
  `app.js` holds `splitSentences`, `refHitsFor` and the `__CONTENT__` self-heal —
  a second retrieval engine feeding the first as a provider. The comment in
  `app.js:573` is careful about this; the README's summary is not.

*Category: unnecessary complexity.*

## What is genuinely sound

Stated so the remediation does not damage it:

- **Derivation over storage is real, not aspirational.** `evidenceGrade`
  (`js/format.js:262`) and `derive` (`js/pipeline.js:63`) are pure functions of
  the records. I re-implemented the first independently and got byte-identical
  counts.
- **Unknown is never zero.** `pipeline.aggregate` returns an unaccounted-for
  count with every figure, by construction.
- **Absence of a rule is not a negative finding.** `js/applies.js` downgrades on
  an unanswered question rather than excluding, and `validate.mjs` forbids any
  rule from asserting `outcome:undetermined` — only the engine may emit it.
- **Failure does not fabricate.** `renderError` leaves surrounding content alone
  and substitutes nothing.
- **The status model has real guardrails.** A `kind:proposal` cannot carry a
  binding `legislative_status`; preliminary findings cannot carry a fine.
- **The README corrects itself in public.** It opens by disowning a previous
  version's instructions. That norm is worth protecting.

## Remediation order

1. **F-02** — put the four validators in CI. Everything else is unenforceable
   until something runs. SESSION 00 classes this green-tier and it closes their
   unresolved issue 3.
2. **F-03 / F-06** — make the one-shot patches inert (rename, or guard behind an
   explicit `--i-have-a-backup` flag), and start writing real commit messages.
   Cheap, and it restores the rollback path the rest depends on. F-04 is now the
   documented proof that leaving them runnable has already corrupted canonical
   data once.
3. **F-04** — extend `validate.mjs` to parse `__CONTENT__` out of `index.html`
   and diff it against `brief.json` and `instruments.json`. This is the single
   highest-value new check in the repository and it closes SESSION 00's
   unresolved issues 1 and 2. **The standfirst itself is the author's call** —
   the evidence above says which copy is stale, not what should ship.
4. **F-05, F-08, F-11, F-12** — close the checks that report success without
   measuring anything.
5. **F-09, F-16** — architectural, expensive, and safe to defer. `docs/HANDOVER.md`
   is explicit that the architecture is the argument and must not be rebuilt.
   Do not start here.
