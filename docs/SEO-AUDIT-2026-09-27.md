# SEO, INDEXING AND DISCOVERABILITY AUDIT — 27 September 2026

**Written before any change was made**, against `main` at `24ca0bb`. Every figure below was
measured on that tree: the raw HTML as served (`fetch`), and the rendered DOM in a real
Chromium driven through this repository's own DevTools client (`agent/browser/cdp.mjs`), for
every URL in `sitemap.xml` plus `instrument.html` and `instrument.html?id=eprivacy`. The live
site was probed with `curl` the same day. Nothing here is inferred from source alone.

What was done about each finding is in `docs/SEO-OPERATIONS.md` and in the commits that follow
this document; this file records the state that motivated them and is not edited afterwards.

---

## 1. Summary

The site is substantively excellent and technically hard to index. The brief (`index.html`) is
88,725 characters of crawlable prose with a clean heading outline. Everything else a search
engine would want to cite — one page per regulation, its dates, provisions, authorities,
enforcement and sources — exists **only after JavaScript runs**, at URLs whose raw HTML declares
a different canonical, carries no `<h1>`, shares one title and one description with twenty
other URLs, and is linked from no static markup anywhere.

## 3. Canonical, indexing and sitemap

- **The canonical model depends on JavaScript.** `js/instrument-page.js` rewrote
  `link[rel=canonical]` and `og:url` to `?id=…` after load; the raw tag names the chooser page.
  A crawler that indexes before rendering sees 21 duplicates of one page declaring themselves
  duplicates of a third. `docs/DEPLOYMENT.md` §6 recorded this as the intended behaviour.
- **The same pattern for languages.** `app.js syncLangUrl()` rewrote the canonical to `?lang=xx`;
  the raw canonical of `?lang=it` is `/`. `hreflang` alternates are only valid between
  self-canonical URLs, so the cluster is invalid in the raw HTML and contradicted in the
  rendered HTML.
- **Sitemap.** 30 URLs: 6 top-level pages, 21 `instrument.html?id=…`, 3 `?lang=…`. 24 of 30 are
  not canonical in their own raw HTML. No `<lastmod>` (deliberately — see §6 of the deployment
  document; the generator had no meaningful date to write). Nine of the 21 instruments are
  records a reader would find thin as a landing page: `ecommerce-directive`, `nis1`,
  `chips-act`, `ai-liability-directive`, `dga`, `eprivacy`, `eidas2`, `gdpr-procedural`,
  `cloud-ai-development-act` — no `dna` record, no objective, few or no dates.
- **Robots.** No `meta robots` on any page. No `robots.txt`, correctly: the host root
  `andreatosti2001.github.io/robots.txt` returns 404 and is not served from this repository.
  **It is not uncontrollable, though:** it would be served by a user-site repository named
  `andreatosti2001.github.io`, which does not exist. Recorded in `docs/SEO-OPERATIONS.md`.
- **Hosting behaviour measured live:** `/instruments` (no extension) is served as
  `instruments.html` (200); `/instruments/` is 404; unknown paths get GitHub's generic 404; HSTS
  is sent; no header can be set.

## 4. Titles, descriptions, social and structured data

- Titles: 7 distinct across 30 sitemap URLs. None contains a searchable name of a regulation
  except by coincidence ("GDPR, DSA, DMA…" is in the homepage *description*, not its title).
- Descriptions: 7 distinct; the instrument description is generic by construction.
- Open Graph: title, description, url, type (`article` on every page, including tool pages
  that are not articles), site name, locale. **No `og:image`.** Twitter `summary`.
- JSON-LD: `WebSite` + `WebPage` + `BreadcrumbList` on every page, built from the title and
  description. Correct in what it omits (no author, no licence, no dates — none is on the
  page). Wrong on instrument URLs (A6), and the breadcrumb name is derived by splitting the title
  on " — ", so it would break with any title change.

## 5. Internal link graph

- Raw HTML, `<noscript>` excluded: `/` → `applies.html`, `instruments.html`. That is the entire
  static graph. The `<noscript>` navigation lists the six destinations, which helps a reader
  and is not a reliable crawl path.
- Rendered: 17 of 21 sitemap instrument ids are linked from somewhere (the comparison table's
  column heads, the interactions view, the instrument chooser). `gdpr-procedural`, `dga`,
  `eprivacy`, `eidas2`, `chips-act` and `ai-liability-directive` are reachable only through a
  typed search in the palette.
- Every rendered link to an instrument uses the query form, so even a rendering crawler is
  steered to the non-canonical representation.

## 6. Localization

Italian, French and Spanish are complete (427/427 strings) and applied by `app.js` in place.
They are not reviewed by a native speaker (README limitation 5). Against the five conditions
for advertising an alternate — same page, materially translated, crawlable, stable URL,
reciprocal — the `?lang=` URLs pass the first, second and fourth, and fail the third and fifth
in the raw HTML. The tool pages are not translated and correctly carry no alternates.

## 7. What is already right and must be kept

The brief's prose, headings and anchors; the evidence apparatus; the CSP (`script-src` hashed,
`style-src 'self'`); self-hosted fonts; zero third-party requests; the `<noscript>` notice and
navigation; the footer written into markup; the refusal to write a `lastmod` it could not
justify; the refusal to ship a `robots.txt` that would be ignored; the absence of any invented
author, date or licence in structured data.

## 8. Decision taken on the evidence

The narrowest change that removes A1–A6 without a framework or a build step: **pre-render the
existing instrument view** — the same renderer the browser runs, called by the existing
generator (`tools/_footer.mjs`) — into one committed static page per substantive instrument at
`/instruments/<id>/`, with CI failing when the committed page is stale. The data stays the one
home of every fact; the static page is a checked projection of it, like the footer and the CSP
hashes already are. The rest follows from that: one canonical per entity, a sitemap generated
from the same route model, JSON-LD built from the same records, and a validator
(`tools/seo-audit.mjs`) that reads the site the way a crawler does.
