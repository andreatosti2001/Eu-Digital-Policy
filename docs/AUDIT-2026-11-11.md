## 2 · P0.1 — what changed

`agent/release/worktree.mjs` (new) and stages 5a–9 of `agent/release/dispatch.mjs`. The four lists of §1.2 are now kept
apart, each from its own source, and the commit is made only when they agree:

1. **Stage 5a `index`** (also in a rehearsal, so a rehearsal never promises a dispatch the execution refuses): refuses when
   anything is **staged** (each path named), any path is **unmerged**, or a **merge, cherry-pick, revert or rebase** is in
   progress. **Nothing is unstaged.** It runs before the branch is cut and before the applier.
2. **Stage 6 `isolate`** takes a **snapshot**: every path `git status` reports, its status column and the sha256 of its
   bytes; the person's own uncommitted bytes are held in memory (cap 32 MiB; above it the dispatch is refused).
3. **Stage 8 `scope`**: **produced** = every path whose status or bytes differ from the snapshot — which now includes an
   applier edit made *inside* a file the person had already changed (invisible before). Refused, with all three lists in
   the report, when produced is empty, when any produced path is not permitted, when git shows a path the applier did not
   declare, or when the applier declared a path git shows unchanged. A disagreement between report and tree is named, never
   reconciled.
4. **Stage 9 `commit`**: only produced paths are staged (one at a time; a deletion with `git rm --cached`); the staged set
   is re-read and must **equal** produced; after `git commit` the commit is re-read and must have **one parent, the base**,
   and **exactly** the produced files. A hook that stages more, or a second parent, makes the commit rejected: the tree is
   detached to the base, rolled back and verified, and the branch carrying the rejected commit is removed only then (so a
   rejected commit cannot later be mistaken for a dispatch by the `Dispatch-Key` search).
5. **The dispatcher's rollback** (distinct from Agent 9's): every path that differs from the snapshot is put back — from the
   base commit for a path that was clean, from the held bytes for a path the person had changed, removed for a path that did
   not exist — and then **verified** by re-reading `git status`, re-hashing every path against the snapshot, checking HEAD
   is the base and the index holds nothing staged. Only then is `origin` checked out and the release branch deleted, and the
   check is repeated. **No `reset`, `clean` or `stash`** (test A11 now also scans `worktree.mjs` for them).
6. **An unverified rollback** reports `severity: "high"`, names every path still wrong and the git error for each (e.g. an
   `index.lock`), **keeps the release branch**, copies the person's held bytes for those paths under the run-log directory
   (`agent/release/runs/recovery-…`, git-ignored), and never says the rollback succeeded. The CLI prints this block.

**Agent 9's rollback is unchanged** (`agent/implement/apply.mjs rollback()`: the permitted paths from the pre-change commit,
re-hashed). The dispatcher now reports it separately (`agent_rollback`) and measures what it left (`residue_after_agent`).
Known limit kept: Agent 9's own `enforceScope()` still subtracts pre-existing dirt (`inherited_dirt`); the dispatcher no
longer relies on it.

### 4.2 Model A (single reviewer) and model B (independent review)

| | **A — single reviewer** (what is in place) | **B — independent review** |
|---|---|---|
| Security | Holds against an agent acting alone (no key; pinned registry; C5/C7/C10). Does **not** hold against a mistaken or compromised author account: one account can change gate, workflow, registry and pin together | Adds a second account that must approve changes to `.github/`, `agent/release/`, `agent/implement/decisions/`, `tools/pages-artifact.mjs` |
| Separation of duties | producer ≠ approver only | producer ≠ approver ≠ second reviewer for protected paths |
| Self-approval | the author approves work the author requested — inherent; it is not an agent self-approval | reduced for protected paths; the author still approves content |
| Single-person dependency | total: key, pin, merge, settings | reduced, but the admin can still change the ruleset |
| Available here now | **yes** | **no**: one collaborator **[GitHub]**; GitHub does not let a sole admin approve their own PR, so the earlier code-owner rule needed the owner on the bypass list — B needs a real second person, registered and pinned |
| Limit left with every gate green | the gate proves that *the key holder* decided, not that anyone else looked; C8's work is unreviewed by construction; a merge commit's own changes are seen by neither C7 nor C8 (§5) | the same limit on truth (C7 shows a person decided, not that they were right) |

**What A must not be called:** independent review. Its compensating controls are the ones measured above — signed decisions,
the hash chain, the external pin, the required `qa.yml` checks **[author]**, the deploy gate, and the author's own reading of
each diff. **Unmitigated under A:** compromise or error of the one account; changes to the gate merged by the same account
that the gate is meant to constrain; no second reader of anything.

| S5 + a page edit made inside a merge commit | FAIL (6) | **pass** |

**Consequences:**

1. **Strict now = no deploy, ever.** `pages.yml` judges from the commit that introduced the gate, and six historical commits
   are in that range forever. Even a commit by the author without any marker (S1) is blocked. No commit can fix it.
2. **Strict after a transition** needs a code change first: a recorded C8 cutoff (or a reviewed baseline of the six). That is
   a change to `agent/release/` and its tests, to be made only on the author's decision.
3. **The manual path survives**: a commit without a marker passes C8 (S1). **So does evasion** (S3): C8 reads a
   self-declared marker, so strict mode rewards a session that does not disclose itself — and AGENTS.md already tells
   sessions to drop the model-naming `Co-Authored-By` line. A blocking check on disclosure punishes honesty.
4. **Merge commits are invisible to C7 and C8** (S5): `readCommits` gives a merge no file list. A page edit made while
   resolving a merge escapes both. This is pre-existing and **not fixed here**.
5. **Practical effect on session work**: under strict + transition, every session commit that touches a published file
   would need a proposal, a signed decision and a dispatch; Agent 9 applies only exact text operations, so changes such as
   the favicon set (binary files) could not go through it at all. The legitimate route left for that work is a commit
   without a marker, i.e. the evasion route of point 3.

**How C8 differs from C5, C7, C10:** C5 asks whether the ledger is intact and signed; C7 whether every commit that *declares*
a proposal is covered by a valid prior decision; C10 whether the signer registry is the pinned one. They judge what is
declared. C8 judges what is *not* declared, by a marker the committer chooses to write.

### 6.1 Decided by the author, 11 Nov 2026 (`docs/ROADMAP-v2.md` §8)

- **D-P0.4-1: model A.** The release chain is a **single-reviewer** model and is described as such, never as independent
  review. Compensating controls: the signed, hash-chained ledger (C5, C6); the per-change binding of decision to commit (C7);
  the registry pinned outside the tree (C10); the deploy gate in the publishing path (C1–C4, C9); the `qa.yml` checks the
  ruleset requires **[author]**; and the author's own reading of each diff before merging. **Left unmitigated:** an error or
  a compromise of the one account; a change to the gate, the workflow, the registry and the pin made and merged by the same
  account the gate constrains; no second reader of anything, including C8's six commits.
- **D-P0.4-2: C8 strict is not activated.** C8 keeps reporting. No change to `gate.mjs`, `pages.yml` or the tests was made
  for P0.4. The stronger control this analysis points to — making the files a merge commit itself changes visible to C7 and
  C8 (§5.4) — is a proposal for a later session, not decided.
